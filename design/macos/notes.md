# 咕咕嘎嘎 · 咕嘎画报（B1）· macOS 端

- 入口：`index.html`（双击即可，需要支持 WebGL2 的 Chromium 内核浏览器）。顶上一条是 **macOS 菜单栏**（能点开：命令和 ⌘ 键是我们定的，画法是系统的）；左栏界面目录和「和电脑端不一样的」清单；右边全部画板，每块画板是一扇 macOS 窗口（圆角 + 桌面投影），下面两排按钮：状态 / 窗口尺寸，和 **macOS**（失焦、系统全屏、菜单栏、刘海屏全屏播放、画中画、正在播放）。
- 单看一扇窗：`board.html?p=<界面>&st=<状态>`，窗口多大版式就按多大排。和电脑端同一套界面 / 状态 / 数据，**`board.html?p=home` 直接全窗口打开就是一个能走通的应用**：导航能跳、能进播放器再退出、⌘ 键能按。
  窗口层的参数：`&blur=1` 失焦、`&fs=1` 系统全屏（红绿灯归系统收走）、`&tl=0` 不画红绿灯（给 Chrome `--app=` 自己的标题栏让位）、播放器 `&full=1` 全屏、`&st=pip` 画中画。
- 单看「整块屏幕」：`screen.html?p=<界面>&st=<状态>&menu=1[&open=<0–6|菜单名>][&annot=1]`、`&fs=1&menu=1`（全屏里鼠标推到顶边、菜单栏滑下来）、`&notch=1`（刘海屏全屏；`p=player` 时画面按刘海规则插边）、`&np=1`（「正在播放」弹出）、`&st=pip&pipwin=1`（系统的画中画小窗）。`board.html` 带这些参数会自己跳到 `screen.html`，所以记一个入口就够。
- 用 Chrome 直接给人看：`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --app="file:///…/design/macos/board.html?p=home" --window-size=1470,956`。Chrome 的 `--app` 窗口在 macOS 上**自带一条原生标题栏（有它自己的红绿灯）**，和我们画的那三颗会重复：要么按 ⌃⌘F 让 Chrome 进全屏（原生标题栏藏起来，看到的就是真机窗口的样子），要么加 `&tl=0` 只看版式。⌘W / ⌘Q / ⌘, 可能被 Chrome 自己接走，真机没有这个问题。
- 截图：`node tools/shots.js [过滤词] --out=<目录>`（清单 `tools/shotlist.js`；默认出到 `shots/`，在 `.gitignore` 里；画面是用户片库的真实海报，不外传、不入库）。
- **这是 Windows 电脑端的 macOS 变体，不是新画的一套版式**。版式、纸面语言、专色、玻璃、她的一切规矩全部沿用 `../desktop/`，遵守 `../../docs/design-language.md`、`glass.md`、`platforms.md` §2、`player.md`、`mascot.md`。`../desktop/` 与 `../../docs/` 一个字节没动。

## 复用，不复制

`board.html` 直接引 `../desktop/css/d*.css` 和 `../desktop/js/*.js`（含玻璃引擎 `engine.js / core.js / glass.js`，原样，不移植进实现），图片包走 `../desktop/pack/`、数据走 `../desktop/js/lib.js`。本目录只有这些文件：

| 文件 | 干什么 |
|---|---|
| `macos.css` | 窗口层：红绿灯本体与报头 / 播放器顶栏的让位、失焦、系统全屏、刘海屏全屏播放的插边、画中画那一页、⌘ 键位表 |
| `macos.js` | 在 `app.js` 之后、`APP.boot()` 之前覆盖 `APP.need / winKeys / mast / chrome / ctxHtml / boot`，加 ⌘ 键、窗口状态参数、把正文里的 Windows 说法换成 macOS 的、接收菜单命令 |
| `macos-menu.js` + `menu.css` | 应用菜单栏：菜单模型（标题 / 命令 / ⌘ 键 / 系统项）+ 系统外观的渲染 + 「正在播放」弹出。画廊和 `screen.html` 共用 |
| `board.html` | 一扇窗口 = 视口；带屏幕层参数时跳 `screen.html` |
| `screen.html` | 整块屏幕：菜单栏 / 刘海那一条 / 系统画中画小窗，窗口本体放在 iframe 里，菜单命令用 `postMessage` 发给它 |
| `index.html` | 画廊 |
| `tools/shots.js` `shotlist.js` | 本机 Chrome 无头截图（CDP + SwiftShader），做法同电脑端，只换了 Chrome 路径、输出目录和清单 |

不复制 50 MB 图片包，不复制玻璃引擎。红绿灯类名 `.tlights`，避开播放器时间轴的 `.tl`。

## 1. 相对 Windows 电脑端改了什么（逐条）

1. **窗口键：右端三键 → 左端红绿灯，报头 = 透明标题栏。** macOS 的关闭 / 最小化 / 全屏在左上角，位置和样子由系统决定（关闭 `#FF5F57`、最小化 `#FEBC2E`、全屏 `#28C840`，12 pt、间距 8，第一颗左边 12 pt；指针移到这一组上三颗一起露出符号；绿灯是「全屏」，按住 ⌥ 才是缩放）。报头照三端统一稿不变（左 `VOL.`、中「咕咕 ◉ 嘎嘎」、右日期）：**上下线仍从页边 `--m` 起，红绿灯坐在线里，是这一行的第一件东西；文字从 85 px 起**（页边比 85 窄时才让，外接大屏 `--m ≥ 85` 时 VOL. 照旧对齐页边）；右端不再留窗口键的位置，日期对齐右页边（和账号圆钮齐）。三颗在报头上下线之间垂直居中（报头 44 高；真机上要用系统的 unified 工具栏样式把它们居中，否则系统默认把它们放在 y ≈ 14，见 §13）。报头可拖、双击按系统偏好缩放或最小化、`VOL.` 仍然可点。
2. **红绿灯是实心的系统元素，不是玻璃，也不走画报的按下放大**（系统按下是变暗）。压在整幅剧照上时给一点投影保证读得清（同报头其余元素的处理）。
3. **窗口失焦**：三颗变灰（`#4b4b4d`），报头的字变淡（55 %）——这是 macOS 对非活跃窗口标题栏的处理；玻璃排、正文都不变（系统也不变）。点进来就恢复。
4. **播放器顶栏**也在左端放红绿灯（返回钮让位到 85 px），右端不再留 Windows 键的位置；播放器进了系统全屏三颗收起（同 Windows 版收起窗口键）。时间轴 `.tl` 不受影响。
5. **应用菜单栏**：Mac 应用必须有，见 §2。Windows 版没有这一层。
6. **键位换成 ⌘**，并补齐 Mac 惯例：`⌘K` / `/` 搜索、`⌘,` 设置、`⌘R` 付印新刊（Mac 没有可靠的 F5：Apple 键盘的 F5 默认是听写 / 键盘背光；F5 仍然能按）、`⌘[` `⌘]` 返回 / 前进（代替 Alt+←）、`⌘1–5` 首页 / 发现 / 片库 / 合集 / 我的（新增，Mac 惯例）、`⌘F` 海报墙筛选（`decisions.md` Q6 的 Ctrl+F）、`V` 收藏、`W` 已看（Q6）、`⌃⌘F` 系统全屏（系统）。播放器键位以上游 `PlayerKeys` 为准，不改。搜索胶囊、账号菜单、首页页脚、设置里的 hint 全部换成 ⌘ 写法；设置 · 播放的快捷键表下面多一张「⌘ 键位（macOS）」表。Ctrl 那套仍然能按（两套并存）。
7. **参考窗口换成 Mac 常见尺寸**：MacBook Air 13″ **1470 × 956**（默认）、MacBook Pro 14″ **1512 × 982**、外接 27″ **2560 × 1440**、最小窗口 1100 × 720（规范的最小尺寸不变）。都是 pt（Retina 下物理像素 ×2，和版式无关）。`1rem = 窗口宽 / 144` 的规则不变：1470 → 10.05 px，2560 → 11.97 px，3168（Windows 的测试分辨率）仍封顶 13。
8. **系统全屏（绿灯 / ⌃⌘F）进一个全屏 Space**：红绿灯归系统收走，**报头留着**——它是画报的报头，不只是标题栏（Windows 全屏同样留报头）；鼠标推到顶边时系统菜单栏滑下来盖在报头上（系统行为，我们不管）。
9. **刘海屏 MacBook 上的全屏播放**：见 §4。Windows 没有这一条。
10. **触控板**：双指左右滑 = 返回 / 前进（和 `⌘[` `⌘]`、鼠标侧键同一件事）；首页海报流、横向海报行双指横滑（Windows 是 Shift + 滚轮）；惯性滚动是系统的；首页封面跨页和目录之间的吸附不变。首页页脚的 hint 从「滚轮 翻页」改成「双指 / 滚轮 翻页」。
11. **播放：画中画、「正在播放」、媒体键**：见 §6。引擎、回退链、`mpv` 字样全部从界面上拿掉，写「待定（上游决定）」——Windows 版的「mpv → VLC → mpv 重试 → 转码」是 Windows 的链，macOS 不编。
12. **设置仍是应用内的一页**（`⌘,` 跳到它），理由见 §7。
13. **更新**：号外上的动作从「下载并更新（MSI，退出后自动装）」改成「下载安装包」（.dmg，拖进「应用程序」替换）；文案见 §8。「关于」里的平台标签改成 macOS；缓存位置 `~/Library/Application Support`、「打开文件夹」→「在访达中显示」；令牌「存在钥匙串里」（Windows 是凭据管理器 / DPAPI）。
14. **右键 = ⌃ 点按也行**（服务器列表那一行提示补了一句）。右键菜单内容不变，仍是纸片。
15. **画廊外壳**：顶上的菜单栏不再是氛围，是 §2 的那份菜单；每块画板是圆角窗口；选了「菜单栏 / 刘海屏」时画板变成整块屏幕（粗边框）。

**没改的（刻意）**：三端统一报头、跨页首页、玻璃排、纸片菜单 / 对话框、专色算法、印章 / 校对勾、字号与间距的所有数值、她的每一格、播放器的十四个状态和「画面让位」。窗口最小 1100 × 720 不变。

## 2. 应用菜单栏

**哪部分是系统的、哪部分是我们的**：菜单栏那一条、苹果菜单、菜单的字体 / 行高 / 高亮色 / 圆角 / 展开动效、「服务」「隐藏」「全部显示」「退出」「撤销 / 重做 / 剪切 / 拷贝 / 粘贴 / 全选」「开始听写」「表情与符号」「最小化 / 缩放 / 前置全部窗口 / 窗口列表」「帮助里的搜索框」——全是 macOS 画的、系统自动加的，我们不写也删不掉（demo 里带「系统」小标，真机菜单里没有这个字）。我们定的只有：七个菜单的标题、每条命令、⌘ 键、可用 / 勾选状态、子菜单。**菜单不是画报语言、不是玻璃、不走按下放大**；应用声明为深色外观，所以菜单是深色的（和「只有深色」一致；菜单栏那一条本身跟桌面走，我们不管）。

## 3. 窗口

- **标题栏**：透明、内容延伸到窗口最顶（报头在 0–44）；红绿灯在左上标准位置；报头整条是拖动区（`VOL.` 和红绿灯除外）；双击标题栏按系统偏好（缩放或最小化）。
- **最小窗口** 1100 × 720（规范）。再窄不重排；播放器可以到 640 × 420（同 Windows）。
- **参考窗口**：1470 × 956 / 1512 × 982 / 2560 × 1440 / 1100 × 720，每个都在画廊里能切。
- **失焦**：§1 第 3 条。
- **缩放（Zoom）**：窗口撑满可见区域（菜单栏和 Dock 之外），不是全屏；版式按缩放后的尺寸重排，报头红绿灯还在。

## 4. 全屏与刘海屏

- 绿灯 / `⌃⌘F` / 播放器里的 `F`：都进同一个全屏 Space（Mac 没有「窗口无边框占满屏幕」这种假全屏，不另造）。红绿灯收走；报头留着（非播放页）；播放器全屏 = 控件照常自动隐去。
- **刘海屏 MacBook（14″ / 16″ / Air 13″ 15″）**：全屏时顶上 **37 pt** 是刘海那一条（菜单栏的位置，自动隐藏后是黑的）。规则：**画面矩形永远不与它相交**，做法是画面区上下各留 37 pt 再居中——
  - 16:9 的片在 1512 × 982 上：画面 1512 × 850.5，上下黑边各 65.75，画面恰好以整块面板为中心、顶边在刘海条以下 28 pt；黑边和刘海条同为纯黑，看不出接缝（全屏播放时播放器的底色从 `#0b0a08` 改成 `#000`，只为了这个）。
  - 4:3 这类高片受高度限制：顶边正好贴在刘海条下沿，一个像素不进去，左右留黑边。
  - 控件出现时，顶栏从刘海条下面开始（顶栏 37 + 64）；画面按「退一步」的规则缩在顶栏和时间轴之间。字幕、弹幕都在画面矩形里，跟着走——`player.md` §1 的「一个像素都不挡」在刘海屏上也成立。
  - 非播放页在全屏里：窗口就在刘海条以下（系统默认），报头从 37 开始；我们不申请把内容伸进刘海两侧。
  - 没有刘海的 Mac（外接屏、老机型）：没有这一条，画面以整屏居中，和 Windows 全屏一样。
- 全屏里鼠标推到顶边，系统菜单栏滑下来盖在报头 / 播放器顶栏上，鼠标离开就收走（系统行为）。

## 5. 触控板与鼠标

- 双指左右滑 = 返回 / 前进；鼠标侧键同；`⌘[` `⌘]` 同。demo 里由 Chrome 代劳（它本来就把双指滑和侧键当成历史前进后退），真机要自己接（§13）。
- 双指上下 = 滚动，惯性是系统的；首页封面跨页和目录之间的吸附不变。
- 首页海报流、横向海报行：双指横滑（demo 里 `.hs` 是原生横向滚动、海报流已经听 `deltaX`，都不用改）。
- 捏合缩放：不用。强按（Force Touch）：不用。
- 右键 = 双指点按 / ⌃ 点按，菜单内容不变（纸片）。

## 6. 播放

- **画中画**：顶栏右半边的「画中画」钮（`player.md` §8）。进了画中画：画面搬进**系统的小窗**（浮在屏幕角上，谁也盖不住，可拖到任何角；系统画它的控件：回到窗口 / 暂停 / 关闭），字幕和弹幕跟着画面走（它们是画面里的字）；主窗口的画面区换成一页纸面说明「画面在小窗里 · 回到这里」。**这一格的能力待定**：取决于上游在 macOS 上接的内核能不能把帧交给系统的画中画（mpv / VLC 子窗口做不到，要内核能输出到 AVSampleBufferDisplayLayer 之类的层）——「有能力才画按钮，没有就不画」是上游规则，没有就没有这个钮。
- **「正在播放」/ 媒体键 / 控制中心**：应用报上去 封面（海报）、片名 logo 对应的片名、「第 5 集 · 集名」、应用名；系统在菜单栏右端和控制中心画「正在播放」，键盘上的播放 / 暂停 / 上下一集媒体键、AirPods 的按键都走它。我们不画任何东西，只提供数据和响应。
- **AirPlay**：规范定的投屏只有 DLNA（用户 2026-11-16）。AirPlay 是 Mac 用户最自然的投屏，但它要内核把画面交给 AVFoundation 的路由——内核是上游的事，这里标**待定**（§12 第 4 条）；「投屏」钮和面板照 `player.md` §8 的 DLNA。
- **引擎 / 回退链**：macOS 上用什么内核、怎么回退，由上游决定。界面上所有写 `mpv`、`d3d11va`、「Windows 上自动回退」的地方都改成「待定（上游决定）」；画质面板的「播放引擎」一组只留「外部播放器…」（手动选）。**不编 macOS 的回退链。**
- **窗口置顶**（播放时）：「窗口」菜单里一条，对应 `player.md` §8 的置顶。
- **锁屏 / 合盖**：播放暂停由系统处理（音频会话），不设计。

## 7. 设置：⌘, 打开的是应用内的一页

Mac 惯例是 `⌘,` 打开独立的「设置」窗口。**这里判断：设置仍是应用内的一页（九个分区，左栏目录、右栏一屏一分区），`⌘,` 和菜单「设置…」都跳到它。** 理由：① 规范里设置是版面的一页，带报头和玻璃导航，是画报的一部分；② 实现上「一个页面一个 `GlassScene`，在应用根」（`glass.md` §2），第二扇窗要再造一套玻璃场景和导航状态，上游的路由模型也是单窗口的；③ 上游的设置树 / 存储是应用级状态，一页里改和一扇窗里改没有差别；④ 独立设置窗口的好处（看着内容改设置）在「画面让位」的播放器面板里已经有了（字幕 / 弹幕的样式都在播放器里直接调）。代价：和纯 Mac 应用的惯例有一点不同——Esc 回上一页而不是关窗。这是取舍，不是红线冲突。

## 8. 更新

Windows 版：应用内查清单 → 下 MSI → 退出后由脚本装好再启动。macOS 上**只写判断，不定技术选型**：
- **分发形态 = `.dmg`**（打开拖进「应用程序」），不进 App Store（GPL-3.0 + 第三方客户端，走不了审核）。
- **必须签名 + 公证（notarize）**：不签的包，Gatekeeper 会拦（「无法打开，因为无法验证开发者」），用户得右键 → 打开或去「隐私与安全性」放行；这在号外上说不清楚，也和「下载完就能用」的承诺冲突。需要主理人的 Apple Developer 账号（§12 第 5 条）。
- **应用内更新**：查清单、验签、比版本、下载——复用上游更新器的通用部分；「装」这一步 macOS 没有 MSI 那种静默替换，两条路：a) 下好 .dmg 直接打开，用户自己拖一次（最省事、不依赖框架，号外上写清楚）；b) 接一个自动更新框架（原生有 Sparkle；JVM 应用用 jpackage 出 .app / .dmg，没有自带更新器）——选哪条等主理人（§12 第 6 条）。demo 按 a) 画：号外的主钮是「下载安装包」，她说的话改成「下载的是 .dmg：打开后把「咕咕嘎嘎」拖进「应用程序」替换旧的，再打开一次就好」。
- 「下载并安装 · 忽略这一版 · 稍后」三个选项（`decisions.md` D15）照旧，只是「安装」在 Mac 上 = 打开 .dmg。
- Windows 那条「覆盖安装后刷新图标缓存」在 Mac 上不存在。

## 9. Dock、拖放、Quick Look

- **Dock 图标菜单**：做，但只放真有用的三条——「继续观看 · 颜心记 第 5 集」（最多三条，直接进播放器）、「搜索…」、「付印新刊」；再往下是系统自己的「选项 / 显示所有窗口 / 隐藏 / 退出」。应用没开时点 Dock 图标就是打开窗口。demo 里没画（它只是一张系统菜单，内容如上）。
- **Dock 图标角标**：不用（没有未读这种东西）。
- **拖放**：不做。拖一个视频文件进来播放不是 Emby 客户端的事（上游也没有本地文件播放）。
- **Quick Look / 服务 / 快捷指令**：不做。
- **通知中心**：只一种——更新号外出现时发一条系统通知（应用不在前台时）；其余不发（她说话不进通知）。

## 10. 遵守的红线（都没动）

- 只有深色，纸是墨黑的；红绿灯是系统的实心元素，**不是玻璃**；菜单栏 / 菜单是系统画的，不是玻璃也不是纸片，不参与设计语言评审。玻璃仍然只在报头下那一排固定导航和固定悬浮钮（播放器的「跳过片头」），demo 的 WebGL 玻璃引擎原样。
- 按下是放大（画报的按钮）；红绿灯按下是变暗——那是系统元素，不归画报管。
- 她只待在留给她的格子里；**正在播放的画面上没有她**：画中画那一页说明里也没有她（画面只是搬走了，没有停）。
- 画面和字幕一个像素都不挡（含刘海屏全屏，§4）。
- 专色、印章朱红、校对勾、宋体 + Georgia 斜体、整幅铺满、海报流——全部沿用电脑端，一个数没改；数值照电脑端 token。
- 返回永远在左上（红绿灯之后的第一个钮）、选项在右；播放器里有收藏。
- 没有给红绿灯 / 窗口加圆角卡片式的投影堆叠；窗口圆角只在画廊的窗框上（系统外壳），内容仍是直角。

## 11. 哪些是示意没做

- **红绿灯不真的关窗 / 最小化 / 全屏**（悬停出符号、按下变暗、失焦变灰是真的）。
- **菜单栏是我们画的系统外观**（SF 字体、13 px、22 px 行、系统蓝高亮、深色菜单），真机上一行都不存在；系统项的具体文案以系统为准。「正在播放」弹出同理。
- **刘海的轮廓**在 demo 里画成极淡的一块（`#0a0a0a`）好让人看见它在哪；真机上它和黑条同色、肉眼不可见。
- 画中画的小窗是示意（真机是系统的 PiP 窗口）；**画中画这个能力本身待定**（§6）。
- 系统全屏里菜单栏「滑下来」只有静态的两张（有 / 无），没有动画。
- `⌘W` `⌘Q` `⌘M` `⌘H` 这些系统键在 demo 里不生效（浏览器的）。
- Dock 菜单、通知、触控板手势的真机行为没画（§5 §9 只写规则）。
- 字体走系统栈（macOS 上是 Songti SC + Georgia），和电脑端 demo 一致；真机是内置的 Noto Serif SC 子集（`decisions.md` Q3）。
- 玻璃折射的是页面重绘，虚化剧照 / 三维海报在玻璃里是近似的——同电脑端 demo 的已知小出入。

## 12. 需要主理人定的事

1. **`⌘1–5` 换页、`⌘R` 刷新、`⌘[ ⌘]` 前进后退**：Mac 惯例，规范的键位表里没有。是否进 `platforms.md` §2（建议进；只在 macOS 生效）。
2. **红绿灯在报头里的垂直位置**：设计是「在报头上下线之间居中」（y ≈ 25）；系统默认把它们放在 y ≈ 14。要居中就得用 unified 工具栏样式（公开 API，但要在壳里配一个空工具栏）；接受默认位置就只需改一个让位数。建议居中。
3. **设置是应用内的一页**（§7）：同意这个取舍，还是要独立设置窗口。
4. **AirPlay**：要不要（取决于上游内核能否把画面交给系统路由）；要的话是「投屏」面板里 DLNA 旁边的一行。
5. **签名与公证**：需要 Apple Developer 账号（每年 99 美元）；不签就要在号外和 README 上写「右键 → 打开」。
6. **更新的「装」怎么做**（§8）：a) 打开 .dmg 用户自己拖；b) 接自动更新框架。建议先 a)。
7. **画中画**：能力由上游内核决定；要不要为 macOS 专门要求内核支持（上游 ADR）。
8. **参考窗口**：是否把 1470 × 956 / 1512 × 982 / 2560 × 1440 写进 `platforms.md`（和 Windows 的 1100 / 1440 / 3168 并列，离屏测试各看一遍）。
9. **Dock 菜单的三条**（§9）：要不要，以及「继续观看」放几条。
10. **菜单栏的「窗口置顶」**：只在播放时可用，还是任何时候都可以。

## 13. 真机落地（只写判断，不写代码）

实现是 `:shell-desktop`（Compose Desktop / JVM，`UiMode.Desktop`）；现在的壳是 Windows 的：上游的窗口栈 `VideoStage`（Win32 两扇窗一起挪）、`StageWindowControls` 实现上游 `WindowControls`（最小化 / 最大化 / 关闭 / 全屏 / 置顶 / `DragArea`）、`DpapiKeyValueStore`、`DesktopUpdateHost`（MSI）、`windowsReducedMotion`、`%APPDATA%\GugaArt`。界面层 `ui/…/desktop/DesktopShell.kt` 的 `DesktopMasthead` 画报头 + 右端 `WindowKeys`。`UiMode` 不变（仍是 `Desktop`，版式一套），差异都在壳和一个「平台样式」开关上：

| 差异 | 落在哪 | 要不要上游开缝 / 新 ADR |
|---|---|---|
| 红绿灯 + 透明标题栏 + 报头让位 | 壳：macOS 的窗口用系统标题栏（透明、内容到顶、红绿灯由系统画）；`WindowControls` 的 macOS 实现只需 `DragArea`（可以直接是系统的可拖区）、`setFullscreen`（进全屏 Space）、`setAlwaysOnTop`。界面：`DesktopMasthead` 按 `deps` 里的「窗口键在哪」（新增一个 `WindowControls.style`：系统左端 / 自绘右端）决定画不画 `WindowKeys`、文字从哪起 | `WindowControls` 是上游接口：加「样式 / 系统按钮占位」要上游改或在 `PlatformDeps` 外另给一个值（`adr/0001` §6 的做法）。**新 ADR**：macOS 壳怎么造窗口（上游的 `VideoStage` 是 Win32 的，macOS 没有它） |
| 红绿灯在报头里居中 | 壳：unified 工具栏样式 + 隐藏标题；不行就接受 y ≈ 14 并把让位数写进 `DesktopSpec` | 壳内解决 |
| 失焦 | 壳把窗口活跃状态塞进 `PlatformDeps`（或 `LocalWindowInfo`），`DesktopMasthead` 读它变淡；红绿灯的灰是系统的 | 只用 Compose 的窗口信息就行 |
| 菜单栏 | 壳：Compose Desktop 的 `MenuBar` / AWT 菜单（macOS 上会变成真的系统菜单栏）；命令调用和界面同一套动作（导航、刷新、搜索、筛选、播放器控制）——这些动作要从界面里抽成一个「命令表」（`ui/…/desktop/DesktopCommands`），快捷键表（上游 `nav/Shortcuts.kt`）和菜单共用同一份 | 上游的 `Shortcuts` 只认键，不认菜单：命令表在本仓库做；播放器那一组要读 `PlayController` 的公开方法（`adr/0002` 的接法） |
| ⌘ 键 | 上游 `Shortcuts.kt` 的修饰键是 Ctrl：macOS 上要把 `⌘` 当主修饰键（`Ctrl+K` ↔ `⌘K`）。`⌘1–5` `⌘R` `⌘[` `⌘]` 新加 | 上游若不支持按平台换修饰键 → 开缝或在本仓库包一层 |
| 系统全屏 | `WindowControls.setFullscreen` 的 macOS 实现 = 进全屏 Space；报头照画，`WindowKeys` 不画 | 壳内 |
| 刘海屏全屏播放 | 壳：读屏幕的安全区（刘海条高度），作为 `PlatformDeps` 的一个值（或 `LocalSafeArea`）给播放器；播放器的「画面区」盒子上下各加这个 inset（§4 的规则），`VideoSurface` 照常把矩形报给内核（`player.md` §9 的 `setViewport`）；全屏时播放器底色 `#000`。JVM 能不能把窗口伸到刘海两侧不重要：伸不进去就是系统默认，规则一样成立 | 壳内 + `ui/…/player/` 一个 inset；内核视口是上游已有的缝 |
| 触控板手势 | 双指横滑 / 侧键：macOS 上 AWT 收不到「swipe」事件，要在壳里接系统的手势（或退一步只接 `⌘[` `⌘]` 和鼠标侧键）；横向滚动 Compose 已有 | 壳内；接不到 swipe 就记进已知差异 |
| 画中画 / 「正在播放」/ 媒体键 | 「正在播放」和媒体键：壳向系统报信息（JVM 没有现成的 Now Playing 接口，要桥一段原生代码）；画中画：**取决于上游在 macOS 上接的内核**，有能力才在 `PlayerPlatform` 里报有 | **上游**：macOS 内核与回退链（待定）；画中画 / 「正在播放」的原生桥是新 ADR 的一部分 |
| 设置 `⌘,` | 命令表里一条，导航到设置路由 | 无 |
| 更新 | 壳：`DesktopUpdateHost` 是 MSI 的，macOS 另写一个「下载 .dmg 并打开」的宿主（上游 `UpdateHost` 接口照用），`GithubUpdate.config` 的资产名加 `macos-dmg`；签名 / 公证进发版脚本（`release.md`） | 上游 `UpdateHost` 接口够用；发版标准（`release-standard.md`）要加 macOS 一节 |
| 存储 / 路径 | `~/Library/Application Support/GugaArt`；安全存储换成钥匙串（上游 `DpapiKeyValueStore` 是 Windows 的，macOS 要另一个 `KeyValueStore` 实现）；减弱动效读系统的「减弱动态效果」 | 壳内；接口是上游已有的 |
| Dock 菜单 / 通知 | 壳：`java.awt.Desktop` 的 Dock 菜单 + 系统通知 | 壳内 |
| 右键 = ⌃ 点按 | Compose 在 macOS 上会把 ⌃ 点按报成右键，不用做 | 无 |

一句话：`UiMode.Desktop` 一套版式不动，macOS 的差异 = 壳里一扇新窗口（系统标题栏、全屏 Space、安全区、菜单栏、钥匙串、.dmg 更新）+ 界面层三个开关（窗口键在哪、活跃与否、刘海 inset）+ 一张命令表。内核相关（引擎、回退、画中画、AirPlay）全是上游的，等上游。
